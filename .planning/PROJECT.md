## What This Is

Мультипользовательский Telegram-бот для контроля личных расходов. Траты попадают в него автоматически — iOS-Команда (автоматизация «Транзакция») при каждой оплате Apple Pay отправляет сумму и продавца на сервер; остальное (наличные, BLIK) быстро вносится вручную сообщением. Бот раскладывает траты по категориям, следит за недельным лимитом, шлёт алерты и сводки с диаграммами. Делается для себя (живу в Польше, iPhone) и как портфолио-проект на C# для позиции Backend Developer.

## Core Value

Каждая оплата Apple Pay автоматически и без дублей попадает в бот, и я в любой момент вижу, сколько осталось от недельного лимита (200 zł).

## Requirements

### Validated

- ✓ Реальная оплата Apple Pay проходит путь iPhone → HTTPS (Oracle, Caddy, DuckDNS) → сервер → Postgres → Telegram с остатком недельного лимита (однопользовательская версия: один токен, без идемпотентности и категорий) — Phase 1
- ✓ Логи без сумм, продавцов и токенов (PRIV-03), проверено на проде — Phase 1
- ✓ Секреты только в `.env`, gitleaks в CI зелёный на PR (FND-05) — Phase 1

### Active

**Онбординг и мультипользовательность**
- [ ] Пользователь регистрируется через `/start` в Telegram, получает личный секретный токен
- [ ] Бот выдаёт ссылку на готовую iOS-Команду и инструкцию по настройке автоматизации «Транзакция» (запуск без подтверждения)
- [ ] Пользователь может перевыпустить токен (`/token`); старый перестаёт работать
- [ ] Данные пользователей полностью изолированы друг от друга

**Приём трат**
- [ ] HTTPS-эндпоинт принимает транзакции от iOS-Команды (сумма, продавец, карта, время) с аутентификацией по токену
- [ ] Приём идемпотентен — повторная отправка той же транзакции не создаёт дубль
- [ ] Команда при сбое сама повторяет отправку 2–3 раза и только потом показывает «не сохранено»
- [ ] Оплата не в PLN не записывается как сумма в злотых — бот просит ввести сумму в PLN
- [ ] Ручной ввод сообщением: `45 такси`; суффикс `!` (`320 куртка !`) — трата вне лимита
- [ ] После каждой траты бот присылает подтверждение: сумма, продавец, категория, остаток недельного лимита
- [ ] Под тратой — кнопки: сменить категорию, «Не в лимит» / вернуть в лимит, изменить, удалить

**Категоризация**
- [ ] Встроенный набор категорий и правил «продавец → категория»
- [ ] Нераспознанная трата сразу записывается в «Другое», бот в том же сообщении спрашивает категорию кнопками
- [ ] Выбор категории пользователем запоминается как персональное правило для этого продавца
- [ ] `/other` — список трат в «Другом» для отложенного разбора

**Лимиты и алерты**
- [ ] Недельный лимит (неделя пн–вс), по умолчанию 200 zł, настраиваемый
- [ ] Режим переноса настраивается: каждая неделя с нуля ИЛИ перенос остатка/перерасхода на следующую неделю
- [ ] Траты, помеченные «вне лимита», не учитываются в лимите, но видны в статистике отдельно
- [ ] Алерты при достижении 80% и 100% недельного лимита

**Баланс**
- [ ] Ручной баланс: `/balance 3200` задаёт/корректирует; траты вычитаются автоматически; рядом с балансом видна давность последней сверки
- [ ] Ручной ввод доходов (`+5000 зп`), увеличивающих баланс

**Отчёты**
- [ ] `/week` — текущая неделя: потрачено/лимит, остаток, разбивка по категориям, траты вне лимита отдельно
- [ ] `/month` — месяц: разбивка по категориям, итоги по неделям, сравнение с прошлым месяцем, вне лимита отдельно
- [ ] PNG-диаграмма (распределение по категориям), генерируемая на сервере, прикладывается к отчётам
- [ ] Автосводки: итог недели в воскресенье вечером, итог месяца 1-го числа
- [ ] Напоминание «проверь автоматизацию», если несколько дней нет трат через Apple Pay

**Качество и портфолио**
- [ ] Автотесты (unit + интеграционные с реальным PostgreSQL)
- [ ] Docker-деплой на VPS с HTTPS, CI/CD через GitHub Actions
- [ ] Публичный репозиторий с README: схема архитектуры, демо, инструкция запуска

### Out of Scope

- Open Banking (PSD2, агрегаторы вроде Enable Banking / GoCardless) — v2; сначала проверить, доступен ли агрегатор частному лицу бесплатно
- Веб-дашборд / Telegram Mini App — v2, после стабильного ядра
- Мультивалютность — пока только PLN
- Настраиваемый день начала недели — v2; в v1 неделя фиксированно пн–вс
- Публичный демо-инвайт в README — чужие данные оказались бы в одной базе с личными; для показа — GIF на фейковых данных
- «Остаток до зарплаты» / дневной лимит — не нужен; фокус на недельном лимите
- LLM-категоризация — v1 обходится правилами + обучением на исправлениях пользователя
- Локализация — бот только на русском
- Нативное iOS-приложение — требует платного Apple Developer ($99/год)
- Накопления, инвестиции, бюджетирование доходов — фокус на расходах
- Реальный банковский баланс — бот не видит счёт без Open Banking; баланс ведётся вручную

## Context

- Пользователь живёт в Польше; банки PKO BP, mBank, Millennium; почти все траты — Apple Pay (iPhone).
- Мотивация: импульсивные траты и нежелание держать всю математику в голове; цель — держать ~200 zł в неделю на текущие расходы.
- Источник данных: iOS Shortcuts — личная автоматизация «Транзакция» (iOS 17+) срабатывает при оплате картой из Wallet и отдаёт сумму, продавца, название карты; может выполнять HTTP-запрос без подтверждения. Пуш-уведомления банковских приложений как триггер на iOS недоступны.
- Бот не может получать сообщения, отправленные им самим, поэтому прямой путь «Команда → Telegram» невозможен — нужен собственный сервер с API.
- Архитектура: логика целиком на сервере (ASP.NET Core API + БД + фоновые задачи); Telegram и iOS-Команда — клиенты/источники. Это позволяет позже добавить веб-дашборд и Open Banking как ещё один источник.
- Основной язык пользователя — C#; проект — витрина для роли Backend Developer, поэтому важны чистая архитектура, тесты, деплой и интересные инженерные решения (идемпотентность, изоляция данных, фоновые задачи, обучаемая категоризация).

## Constraints

- **Платформа**: iOS без Apple Developer Program — только встроенные Команды; всё законно
- **Tech stack**: C# / .NET (актуальная LTS), ASP.NET Core, PostgreSQL + EF Core, Telegram.Bot (webhook) — предварительно, уточняется исследованием
- **Хостинг**: строго бесплатно — Oracle Cloud Always Free VM + Docker Compose, поддомен DuckDNS с HTTPS; сервер доступен 24/7. Аккаунт Oracle переведён на Pay As You Go (в пределах Always Free это бесплатно), шифрованные бэкапы хранятся вне Oracle. Всё в Docker, чтобы при необходимости переехать (например, на Hetzner ~6 €/мес) без переделок. Vercel/Netlify/GitHub Pages/Cloudflare Pages/Workers не подходят (нет .NET-бэкенда 24/7); Render free засыпает и теряет транзакции
- **Валюта**: только PLN
- **Язык интерфейса**: русский
- **Безопасность**: токены хранятся хэшированными; финансовые данные пользователя изолированы
- **Сроки**: не жмут — качество важнее скорости
