# Requirements: Finance Bot

**Defined:** 2026-11-14
**Core Value:** Каждая оплата Apple Pay автоматически и без дублей попадает в бот, и я в любой момент вижу, сколько осталось от недельного лимита (200 zł).

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Validation Spike

- [ ] **SPIKE-01**: Собран корпус реальных payload'ов iOS-автоматизации «Транзакция»/«Wallet» с iPhone пользователя (карты PKO BP, mBank, Millennium): формат суммы, даты, продавца; случаи — сумма ≥1000 и <1 zł, отклонённая оплата, пустая сумма/продавец, иностранная валюта, возврат, Apple Watch, авиарежим, поведение «Получить содержимое URL» при 4xx/5xx
- [ ] **SPIKE-02**: Проверено, может ли шаблон Команды через «Вопросы при импорте» принять токен без вшивания секрета

### Foundation & Delivery

- [ ] **FND-01**: Решение из 5 проектов (Domain, Application, Infrastructure, Telegram, Api) + тестовые проекты; архитектурные тесты проверяют направление зависимостей
- [ ] **FND-02**: Сервис развёрнут бесплатно на Oracle Cloud Always Free VM через Docker Compose (app, migrator, postgres, caddy) и доступен по HTTPS на поддомене (DuckDNS); `/health` отвечает
- [ ] **FND-03**: CI (GitHub Actions) собирает, прогоняет тесты (включая интеграционные с реальным PostgreSQL) и деплоит при пуше в main
- [ ] **FND-04**: Миграции БД применяются отдельным одноразовым шагом (EF migration bundle) при деплое
- [ ] **FND-05**: Секреты не попадают в репозиторий (gitleaks в CI, .gitignore с первого коммита)
- [ ] **FND-06**: Ежедневный бэкап БД за пределы сервера; восстановление проверено хотя бы раз

### Registration & Access

- [ ] **ACC-01**: Пользователь регистрируется через `/start` в Telegram
- [ ] **ACC-02**: Режим регистрации задаётся настройкой сервера (`open` / `invite`), по умолчанию `invite`; в режиме `invite` без валидного кода регистрация невозможна
- [ ] **ACC-03**: Администратор может создавать инвайт-коды
- [ ] **ACC-04**: После регистрации пользователь получает личный секретный токен (хранится на сервере только в хэшированном виде)
- [ ] **ACC-05**: Пользователь может перевыпустить токен командой `/token`; старый сразу перестаёт работать
- [ ] **ACC-06**: Пользователь видит только свои данные — ни API, ни кнопки Telegram не дают доступа к данным другого пользователя
- [ ] **ACC-07**: Бот работает только в личных чатах; вебхук Telegram проверяет секретный заголовок и не обрабатывает одно обновление дважды

### Shortcut Ingestion

- [ ] **ING-01**: Пользователь получает ссылку на готовую iOS-Команду и инструкцию на русском по настройке автоматизации (запуск без подтверждения)
- [ ] **ING-02**: После настройки пользователь может сделать тестовую отправку и получить от бота подтверждение, что связка работает
- [ ] **ING-03**: При оплате Apple Pay трата (сумма, продавец, карта, время) автоматически сохраняется на сервере через HTTPS-эндпоинт с аутентификацией по токену
- [ ] **ING-04**: Суммы в локализованном формате (`1 234,56 zł`, неразрывные пробелы, запятая) распознаются корректно; исходная строка сохраняется
- [ ] **ING-05**: Повторная отправка той же транзакции (ретрай сети) не создаёт дубль
- [ ] **ING-06**: Почти одинаковая трата (та же сумма, продавец, карта в пределах ~2 мин) помечается как дубль и не идёт в лимит; кнопка «Это была отдельная покупка» возвращает её
- [ ] **ING-07**: Если банк не передал сумму, трата не теряется — бот просит ввести сумму
- [ ] **ING-08**: Команда проверяет ответ сервера и показывает на iPhone уведомление «не сохранено», если запись не удалась

### Manual Entry & Editing

- [ ] **MAN-01**: Пользователь вносит трату сообщением: `45 такси` или `такси 45`
- [ ] **MAN-02**: Суффикс `!` (`320 куртка !`) сохраняет трату вне лимита
- [ ] **MAN-03**: После каждой траты (авто или ручной) бот присылает подтверждение: сумма, продавец, категория, остаток недельного лимита
- [ ] **MAN-04**: Под подтверждением — кнопки: сменить категорию, «Не в лимит» / «Вернуть в лимит», изменить, удалить
- [ ] **MAN-05**: Пользователь может изменить сумму или дату траты
- [ ] **MAN-06**: Удаление траты можно отменить (undo); сообщение обновляется на месте

### Categorization

- [ ] **CAT-01**: Встроенный набор категорий (Продукты, Кафе, Транспорт, … , Другое) и правил «продавец → категория» для популярных польских продавцов
- [ ] **CAT-02**: Нераспознанная трата сразу записывается в «Другое», и бот в том же сообщении предлагает выбрать категорию кнопками
- [ ] **CAT-03**: Выбранная пользователем категория запоминается как личное правило для этого продавца
- [ ] **CAT-04**: `/other` показывает список трат в «Другом» для отложенного разбора

### Weekly Limit & Alerts

- [ ] **LIM-01**: Недельный лимит (по времени Europe/Warsaw), по умолчанию 200 zł; пользователь может изменить его
- [ ] **LIM-07**: Пользователь может выбрать день начала недели (по умолчанию понедельник); изменение вступает в силу со следующей границы недели
- [ ] **LIM-02**: Режим переноса настраивается: каждая неделя с нуля ИЛИ перенос остатка/перерасхода на следующую неделю (без потолка)
- [ ] **LIM-03**: Пользователь может вручную сбросить накопленный перенос
- [ ] **LIM-04**: Траты вне лимита не учитываются в лимите, но видны в статистике отдельно
- [ ] **LIM-05**: Бот предупреждает при достижении 80% и 100% недельного лимита — по одному разу за неделю на каждый порог
- [ ] **LIM-06**: Остаток лимита всегда пересчитывается из истории трат — изменение или удаление старой траты корректно отражается

### Balance

- [ ] **BAL-01**: `/balance 3200` задаёт или корректирует текущий баланс
- [ ] **BAL-02**: Траты автоматически уменьшают баланс
- [ ] **BAL-03**: Доход вносится сообщением `+5000 зп` и увеличивает баланс
- [ ] **BAL-04**: Пользователь может посмотреть текущий баланс

### Reports

- [ ] **REP-01**: `/week` — текущая неделя: потрачено / лимит, остаток, разбивка по категориям, траты вне лимита отдельно
- [ ] **REP-02**: `/month` — текущий месяц: разбивка по категориям, итоги по неделям, сравнение с прошлым месяцем, траты вне лимита отдельно
- [ ] **REP-03**: К отчётам прикладывается PNG-диаграмма распределения по категориям (с корректной кириллицей)
- [ ] **REP-04**: Автосводка недели приходит в воскресенье вечером, сводка месяца — 1-го числа (по времени пользователя), ровно один раз, даже после перезапуска сервера

### Privacy

- [ ] **PRIV-01**: `/privacy` объясняет, какие данные хранятся и зачем
- [ ] **PRIV-02**: `/deleteme` удаляет все данные пользователя после подтверждения
- [ ] **PRIV-03**: Логи не содержат сумм, продавцов и токенов

### Portfolio

- [ ] **PORT-01**: Публичный README: схема архитектуры, ключевые решения (ADR), инструкция запуска, демо (GIF) на фейковых данных, демо-инвайт-код

## Out of Scope

| Feature | Reason |
|---------|--------|
| Мультивалютность | Только PLN; иностранные оплаты — v1.x через запрос суммы в PLN |
| Дневной лимит / «остаток до зарплаты» | Цель — недельный лимит |
| LLM-категоризация | Правила + обучение на исправлениях достаточно для v1 |
| Локализация | Бот только на русском |
| Нативное iOS-приложение | Требует платного Apple Developer |
| Накопления, инвестиции | Фокус на расходах |
| Реальный банковский баланс | Недоступен без Open Banking; баланс ведётся вручную |
| Тихое удаление дублей | Дубли скрываются с возможностью вернуть — ничего не теряется |
| Подтверждение перед каждым удалением | Вместо этого undo |
| Групповые чаты / общий бюджет | Только личные чаты, каждый пользователь отдельно |

## Open Decisions (resolve in discuss-phase for the Limits phase)

- С какой недели действует изменение лимита/режима (текущая или следующая граница недели)
- Переходная неделя при смене дня начала недели (длиннее/короче — как считать лимит)
- Первая (неполная) неделя после регистрации
- Обработка возвратов (refunds)
- Алерты отдельным сообщением или жирной строкой в подтверждении
- Пустые недели — слать короткую сводку или пропускать
