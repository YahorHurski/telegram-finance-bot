# iOS-Команда: отправка оплат Apple Pay в бот

Автоматизация «Транзакция» срабатывает после каждой оплаты через Wallet / Apple Pay и отправляет сумму, продавца, карту и время на сервер. Подтверждение приходит в Telegram.

**Ограничение:** автоматизация видит только оплаты через Wallet / Apple Pay. Наличные, BLIK и оплату картой без телефона она не видит.

Перед началом нужны:
- адрес сервера `https://<поддомен>.duckdns.org` (см. [deploy.md](deploy.md));
- значение `Bot__IngestToken` из `.env` на VM.

## 1. Автоматизация

Приложение «Команды» → вкладка «Автоматизация» → «+» → **«Транзакция»**:
- Карты: **все**;
- **«Выполнять сразу»** (в некоторых версиях iOS — «Запускать сразу»);
- «Уведомлять о запуске»: **выключено**.

Далее «Новая пустая команда».

Отладочная автоматизация «Транзакция» → «Добавить в заметку» (корпус для спайка Phase 3) может работать параллельно с этой: iOS запускает обе.

## 2. Действия

**Действия 1–2. «Текст» для суммы и карты**

Переменные «Сумма» и «Карта» в автоматизации типизированы (число с валютой, карта Wallet). Если вставить их в JSON напрямую, iOS может отправить не строку. Поэтому каждую оберни в отдельное действие **«Текст»**:
- «Текст» → внутри переменная **Сумма** (результат: строка вида `1,20 zł`);
- «Текст» → внутри переменная **Карта**.

Время можно отправлять как есть: переменная **Дата** из автоматизации превращается в русскую строку, и сервер понимает оба варианта, которые выдаёт iOS: `17.11.2026, 12:03` и `17 нояб. 2026 г., 12:03`. Отдельное действие «Формат даты» не нужно (если оно уже есть со строкой `dd.MM.yyyy HH:mm:ss`, это тоже работает). Если время не разобрано, сервер берёт время получения запроса.

**Действие 3. «Получить содержимое URL»**
- URL: `https://<поддомен>.duckdns.org/api/v1/transactions`
  Путь `/api/v1/transactions` не меняй: он зафиксирован на сервере, и при смене пришлось бы переделывать Команду.
- Метод: **POST**.
- Заголовки (ключ пишется буквально):
  - ключ `Authorization`, значение `Bearer <токен>` (слово Bearer, пробел, значение `Bot__IngestToken`);
  - ключ `Content-Type`, значение `application/json`.
- Текст запроса: **JSON**, четыре поля, у всех тип **«Текст»**:

  | Ключ | Значение |
  |------|----------|
  | `amount` | результат «Текст» с Суммой |
  | `merchant` | Продавец |
  | `card` | результат «Текст» с Картой |
  | `time` | Дата (переменная автоматизации) |

  Ничего на iPhone не обрабатывай: сервер сам разбирает сумму вида `45,99 zł` и время.

**Действие 4. «Если»**
- Условие: «Содержимое URL» **не содержит** `"id"` (с кавычками).
- Внутри «Если»: **«Показать уведомление»** с текстом **«Трата не сохранена»**.
- Ветку «Иначе» оставь пустой.

При успехе сервер отвечает `201` и `{"id":"..."}`, Команда молчит, а подтверждение приходит в Telegram.
При ошибке (неверный токен `401`, ошибка сервера `5xx`) в ответе нет `"id"`, и ты увидишь уведомление. Проверено на устройстве 2026-11-17: с испорченным токеном сервер ответил 401, и уведомление «Трата не сохранена» пришло.

## 3. Проверка

Оплати что-нибудь через Apple Pay. Через пару секунд в Telegram придёт подтверждение вида `− 45,99 zł · Продавец` и остаток недельного лимита.

**Ручной запуск — не проверка.** Если запустить автоматизацию «Транзакция» кнопкой, у неё нет данных оплаты: поля приходят пустыми. Сервер всё равно сохранит запрос (201), а бот пришлёт `⚠️ Не разобрал сумму`. Это ожидаемо, такая запись в лимит не идёт. Проверять Команду нужно настоящей оплатой.

## Безопасность

- Команда с вписанным токеном — это секрет. Не делись ею и не выкладывай её скриншоты.
- Если токен утёк: на VM поменяй `Bot__IngestToken` в `.env` (`openssl rand -hex 32`), выполни `docker compose up -d` и впиши новый токен в Команду.

## Что не проверено

Поведение «Получить содержимое URL» без сети (авиарежим) и при ответах 5xx на устройстве не проверялось: по опыту сообщества при 5xx действие отдаёт тело ответа, а без сети iOS показывает свою ошибку. Это проверяется в спайке Phase 3.
